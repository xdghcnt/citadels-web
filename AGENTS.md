# Памятка по Citadels Web

## Назначение и первое знакомство

Это пакет веб-игры «Цитадели Делюкс», подключаемый к отдельному хосту `ws-server-engine`. Сервер написан на CommonJS, клиент — React с JSX, который компилируется Babel прямо в браузере. Отдельной сборки и фронтенд-пакетного менеджера нет.

Перед изменениями проверь `git status --short`, текущую ветку и фактический корень репозитория. Не откатывай чужие изменения. Commit и push выполняй только по прямому запросу пользователя; разрешение на commit не означает разрешение на push.

Начни чтение с этих файлов:

| Файл | Что в нём |
|---|---|
| `README.md` | Полная настройка локального хоста, WSL, формат сетапа и правила настройки партии |
| `public/setup.js` | Каталог, значения по умолчанию, валидация, импорт/экспорт JSON и хранение черновика формы |
| `utils.js` | Создание колоды, перемешивание, раздача, добор и сброс кварталов, случайный сброс персонажей |
| `module.js` | Точка входа пакета, `GameState`, серверная машина состояний, способности, очки, таймеры, сохранения |
| `public/app.jsx` | Компоненты игры, форма настроек, просмотр сетапа и обработка WebSocket-событий |
| `public/app.html`, `public/style.css` | Подключение клиентских ресурсов и стили |
| `test/` | Юниты и серверные сценарии на встроенном `node:test` |
| `autotests/README.md` | Пять JSON-паков и два воспроизводимых браузерных сценария |

`package.json` экспортирует `module.js` под именем `citadels`. `npm test` запускается здесь; `npm start` — в папке хоста. Корневой `app.js` не является основным способом запуска: актуальная конфигурация хоста приведена в README.

## Архитектура и поток данных

```text
Хост ws-server-engine
  └─ require("citadels")(wsServer, "/bg/citadels")
       └─ module.js / GameState
            ├─ utils.js → public/setup.js
            ├─ публичный room → событие state → public/app.jsx
            └─ закрытый state.players[slot] → player-state конкретному игроку

public/app.html → public/setup.js → public/app.jsx + public/style.css
```

`init(wsServer, path)` регистрирует страницу через `registry.handleAppPage`, статические файлы под `/citadels` и менеджер комнат. Движок предоставляет HTTP/WebSocket, комнаты, идентификацию пользователей, общие клиентские библиотеки и сохранение снимков. HTML нужно открывать по `/bg/citadels`: прямое открытие файла или корня сайта не заменяет страницу, в которую движок добавляет зависимости и токен соединения.

В `module.js` есть два разных состояния:

- `room` — публичные данные: места игроков, открытые кварталы, ресурсы и их количества, текущая фаза, таймер, счётчики колоды и сброса. `update()` передаёт их всем подключённым, включая наблюдателей. `gameSetup` хранится здесь для snapshots, но исключается из обычного события `state` и отправляется отдельно.
- `state` — закрытое серверное. Здесь руки игроков, порядок колоды, стопка сброса, назначения персонажей, история случайного сброса и служебные данные способностей. `sendState(user)` отправляет только состояние соответствующего игрока. Не добавляй закрытые карты или скрытые роли в публичный `room`.

Фазы партии:

| `room.phase` | Значение |
|---:|---|
| `0` | Лобби или законченная партия |
| `1` | Выбор персонажей |
| `1.5` | Обмен через Театр |
| `2` | Основной ход |
| `3` | Дополнительный выбор или ответное действие |

Конкретный допустимый ответ также зависит от `state.players[slot].action`. `userEvent` направляет события в `userEventHandlers` или `slotEventHandlers`. Ограничения роли, фазы и текущего игрока должны проверяться на сервере; скрытая кнопка не является проверкой прав.

Основной цикл: `startGame` → `newRound` → `nextChoose`/`nextChoose2` → `nextCharacter` → `finishTurn` → `endRound`. Достроенный город запускает окончание партии в конце раунда, а не немедленно. Таймеры используют те же пути завершения и выбора; после изменения ответа способности проверь также истечение таймера.

## Сетап и важные инварианты

`public/setup.js` — общий UMD-модуль: Node получает его через `require`, браузер — как `CitadelsSetup`. Доменные ограничения добавляй здесь, затем используй их на клиенте и сервере. Не создавай расходящиеся копии каталога или проверки.

Формат `citadels-setup`, версия 1:

- `districts.basic` — число копий каждого базового квартала; `districts.unique` — выбранные особые кварталы; `characters` — упорядоченный набор ролей.
- `timer` — включение, пресет и три длительности в миллисекундах.
- `starting` — размер руки, минимум/точное число особых, золото и уменьшения ресурсов первой короны.
- `rules` — размер города, бонусы и запрет повторного случайного сброса.
- `metadata` — дополнительные сведения о наборе.

Новые необязательные поля должны получать значения по умолчанию при чтении старых файлов. Нормализация проверяет структуру; `getStartErrors` дополнительно проверяет возможность старта с текущим составом комнаты. Структурно корректный файл может содержать неподходящего персонажа: оставь его выбранным и покажи причину запрета старта. Ограничения Театра проверяются отдельно как ограничения квартала.

`undefined` в базовой колоде означает стандартные 54 карты; явный пустой объект — ноль базовых карт. Не смешивай эти случаи. Все выбранные особые включаются в колоду, ограничения 14 карт нет.

Перед стартом проверяются достаточность карт для всех рук, число особых, число базовых при точном режиме, размер и разнообразие колоды относительно размера города. Отказ должен происходить до изменения игрового состояния. Старые аргументы `start-game` поддерживаются; новые параметры передаются последним необязательным объектом `{starting, rules}`.

Корона назначается случайно до раздачи. Уменьшения применяются только к её первому владельцу на старте; минимум/точное число особых действует и для его руки. Нельзя автоматически снижать минимум ради уменьшенной руки. Индекс руки в плотном массиве игроков не равен номеру места: в `playerSlots` бывают пропуски.

`citySize: null` означает 8 для троих, 7 для остальных составов 2–8; ручной порог — 2–10. В активной партии используй сохранённый `state.maxDistricts`, а не заново вычисленный порог. Он влияет на завершение, защиту города и связанные способности.

`firstCity` — полный независимый бонус первому завершившему. Он сохраняется и после жертвы Арсеналом. `otherCities` начисляется остальным при достигнутом пороге города на момент подсчёта. `allColors` участвует в выборе наиболее выгодного цвета Квартала призраков. Ноль отключает соответствующий бонус.

Черновик формы хранится в `sessionStorage` через `CitadelsSetup.createDraftStore`, отдельно по userId и roomId. Он переживает F5 в той же вкладке, но не гарантирует восстановление после её закрытия. Дополнительного TTL и проверки времени нет: срок жизни определяет браузерная сессия. Повреждённые записи удаляются при чтении; при ошибках доступа к хранилищу форма остаётся рабочей. Сохраняется только последний корректный сетап, а не незавершённые числовые поля. Не возвращай сетевые отправки из жизненного цикла редактора.

Движок кэширует `app.html` в памяти до перезапуска, а скрипты отдаёт с диска. Поэтому новый обязательный `<script>` может отсутствовать в старом HTML при уже обновлённом `app.jsx`. Хранилище включено в существующий `setup.js`, и браузерный сценарий проверяет работу без отдельного скрипта хранения.

`gameSetup` фиксирует настройки начатой партии. Сервер отправляет его событием `game-setup` только вошедшему пользователю и всем участникам при старте новой партии; обычный `state` исключает это поле. Клиент сохраняет его независимо от частых игровых обновлений. До первой партии `SetupViewer` показывает отсутствие сетапа, в лобби после игры — последний начатый сетап. Событие `update-setup` больше не обрабатывается, старые поля `setupDraft*` удаляются при восстановлении snapshots.

Только хост может менять, импортировать и экспортировать настройки до старта. Проверяй смену фазы/хоста и после асинхронного чтения файла. `SetupViewer` предназначен только для просмотра.

Вторая кнопка «По умолчанию» после бонусов сбрасывает четыре блока: стартовые ресурсы, уменьшения первой короны, размер города (в автоматический режим) и бонусы. Она сохраняет колоду, персонажей, таймер и запрет повторного случайного сброса, расположенный под базовой колодой.

## Карты, случайность и сохранения

- Карта квартала в игре — объект `{type, cost, kind}`; в каталоге поле `type` обозначает цвет, а в объекте карты — строковый ID квартала. Особые имеют `kind === 9`.
- `drawDistrictCards` возвращает только реально доступные карты. При исчерпании колоды он перемешивает сброс и продолжает добор; если пусты обе стопки, возможен частичный или пустой результат.
- `discardDistrictCards` потребляет переданный массив. Передавай отделённые карты через `splice`, учитывай владение массивом. Не копируй карту одновременно в руку и сброс.
- Невыбранные карты добора, разрушенные кварталы и содержимое разрушенного Музея идут в отдельный сброс. Не возвращай их напрямую в колоду. Счётчики руки меняй на фактическое число карт.
- `choose` может содержать карты колоды, чужую руку или персонажей. Учитывай `chooseSource` и действие игрока: нельзя безусловно отправлять любой незавершённый выбор в сброс кварталов.
- `preventRepeatedRandomDiscard` относится только к серверному случайному сбросу персонажей в соседних раундах: открытому, закрытому и дополнительному для троих. Ручной сброс в дуэли и способности не ограничены. История остаётся закрытой, сохраняется в snapshot и очищается при новой партии.
- `getSnapshot`/`setSnapshot` работают с `room` и `state`. В старом снимке может не быть новых полей и даже всего `gameSetup`. Сохраняй текущие карты, руки и порог города; отсутствующий сброс считай пустым. Если исходный сетап не сохранён, не выдавай настройки следующей партии за исторические.

Тесты случайной логики должны проверять состав, количества, ограничения и сохранность карт, а не конкретный порядок. В тестах очков задавай руки явно: случайное Тайное убежище даёт дополнительные очки в конце партии.

## Локальный запуск: Windows, Linux, macOS

Нужны Node.js с npm, Git и доступ к приватному репозиторию движка. Проверенная конфигурация и оба полных файла хоста находятся в [README.md](README.md). Не добавляй токены в Git URL, документацию или логи; локальные файлы соседнего хоста могут содержать credentials.

Папки располагаются рядом:

```text
Code/
  citadels-web/
  meme-police/
```

В `meme-police/package.json` зависимость игры — `"citadels": "file:../citadels-web"`, скрипт запуска — `"start": "node app.js"`. Движок закреплён в README на конкретной ревизии. После создания `package.json` и `app.js` по README:

```sh
cd ../meme-police
npm install
npm start
```

Адрес конфигурации из README: `http://localhost:3000/bg/citadels#local-test`. Хеш — имя комнаты. Для разных игроков используй отдельные профили браузера: движок отключает старое соединение при входе с тем же userId из другой вкладки.

Порт задаётся конфигурацией хоста. Пример README читает `PORT` и `ORIGIN`; существующий локальный `app.js` может содержать фиксированные значения и игнорировать эти переменные. Проверяй фактический конфиг, не обещай адрес по одному имени команды `npm start`.

В Linux/macOS: `PORT=3001 ORIGIN=http://localhost:3001 npm start`. В PowerShell сначала задай `$env:PORT = "3001"` и `$env:ORIGIN = "http://localhost:3001"`, затем выполни `npm start`.

После изменений сервера или `public/setup.js` перезапусти хост. Для клиентских изменений обнови страницу; у `setup.js` нужны оба действия. Режим `node app.js debug` включает особые тестовые ресурсы и не подходит для обычной проверки раздачи.

## Отдельно: WSL

Устанавливай и запускай зависимости Linux-инструментами внутри WSL; не смешивай их с Windows npm. Предпочтительная структура — `~/Code/citadels-web` и `~/Code/meme-police`.

```sh
command -v node
command -v npm
node -p process.platform
cd ~/Code/meme-police
npm install
npm start
```

`process.platform` должен быть `linux`, пути Node/npm не должны указывать в `/mnt/c`. Из Windows файлы доступны через `\\wsl.localhost\Ubuntu\home\ivan\Code\citadels-web`; номинальная папка `C:\Code\citadels-web` не обязательно является этой рабочей копией.

Если браузер Windows не видит localhost, сначала проверь сервер в WSL:

```sh
ss -ltnp
curl -I http://localhost:3000/bg/citadels
hostname -I
```

Используй фактический IPv4 WSL и порт слушающего процесса: `http://<IP-WSL>:3000/bg/citadels#local-test`. IP может измениться после перезапуска WSL; не сохраняй его как постоянный адрес. При прямом обращении по IP задай такой же origin в конфигурации хоста.

В NAT-режиме перенаправлением localhost управляет `%USERPROFILE%\.wslconfig` на Windows:

```ini
[wsl2]
localhostForwarding=true
```

Для применения требуется перезапуск WSL. Не делай `wsl --shutdown` без учёта других запущенных задач: он останавливает все дистрибутивы. Предупреждение WSL о Windows-прокси localhost и перенаправление порта игры — разные механизмы.

## Тестирование

Быстрая проверка из папки игры не требует движка или установки npm-зависимостей:

```sh
npm test
node --test test/setup.test.js test/party-settings.test.js
node --test test/deck.test.js test/utils.test.js
node --test test/start-game.test.js test/setup-client.test.js
node --test test/setup-storage.test.js
```

`start-game.test.js` поднимает `GameState` с заглушкой реестра и проверяет события, очки, карты, таймеры, snapshots и частоту отправки сетапа. `setup-client.test.js` выполняет настоящие части классов клиента без JSX: закрытие редактора, проверку доступа, завершение импорта и локальное сохранение без сетевых сообщений. `setup-storage.test.js` проверяет срок жизни сессии, изоляцию комнат/пользователей и отказ хранилища. Не заменяй эти тесты копией проверяемой логики.

JSX нельзя проверить обычным `node --check`. Используй браузер или Babel, поставляемый установленным соседним движком. Для обычного JS полезны `node --check module.js`, `node --check utils.js`, `node --check public/setup.js`; перед коммитом — `git diff --check`.

Браузерные тесты описаны в [autotests/README.md](autotests/README.md). Из папки игры запусти изолированный хост, затем в другом терминале раннер:

```sh
node autotests/ui-host.cjs
# В другом терминале:
npm install --no-save --package-lock=false @playwright/cli@0.1.22
node autotests/run-ui.cjs node_modules/@playwright/cli/playwright-cli.js http://localhost:3002
```

Нужны установленный Chrome и зависимости соседнего `meme-police`. Раннер принимает путь к уже установленному CLI первым аргументом, поэтому повторная установка не обязательна. Тестовый хост хранит данные во временной папке; результаты и служебные файлы браузера находятся в игнорируемом `output/playwright/`.

Для комбинации WSL-сервер + Windows-браузер запусти тестовый хост в WSL с `ORIGIN=http://<IP-WSL>:3002`, а раннер — Windows Node с тем же URL. Проверки создают разные профили для хоста, игрока и наблюдателя. Они охватывают раздачу короне, импорт/экспорт, восстановление черновика после F5, отсутствие трафика при редактировании, получение сетапа при старте/входе и мобильные счётчики. После тестов останови только запущенный тобой тестовый хост.

Выбирай проверки по изменённому поведению. При изменении карт проверь сохранность всех объектов и пустые стопки; при изменении настроек — старый JSON и отказ без мутации; при изменении фаз — обычный ответ и таймер. Не повторяй полный UI-прогон после чисто текстовой правки документации.
